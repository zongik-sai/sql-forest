# 집중모드: 화면 가림과 일시정지

> **2026-10-15 선생님 결정으로 단원 학습에 '단원 집중 학습'을 추가했다(아래 마지막 절).** 단원 화면에서는 이 절이 앞의 '벌점 없음'·'전체화면은 선택' 원칙보다 우선한다. 최종 진단 등 단원 밖 학습 화면은 앞의 규칙(가림·다시 시작, 벌점 없음) 그대로다.

## 요구의 정확한 구현 범위
다른 탭/창/프로그램으로 전환하여 이 학습 창의 포커스가 사라지거나 document가 hidden이면 학습 화면을 가리고 멈춘다. 다른 프로그램이 실행 중이라는 이유만으로 정지하지 않는다. 웹앱은 다른 앱 목록, 다른 탭 주소, 분할화면의 모든 창, 두 번째 모니터의 시선을 알 수 없다. 도구 설명에 이를 명확히 기록한다. 외부 앱 감시·프로세스 검사·키보드 차단을 추가하지 않는다.

## 상태기계
상태: active, paused, readyToResume. 학습 세션 시작 시 visible && document.hasFocus()인 경우에만 active.
- visibilitychange(hidden), window.blur, pagehide → 즉시 paused, 가림 표시, 입력/제출/타이머/애니메이션 잠금.
- focus 또는 visibilitychange(visible) → visible && hasFocus일 때 readyToResume. 자동 재개 금지.
- '학습 계속하기' → visible && hasFocus 재확인, active.
- 수동 휴식 → paused. 돌아오기 방식은 동일.

로그인 redirect는 학습 세션 전에 수행하여 시작 화면을 잠그지 않는다. 앱 내부 에디터 포커스 이동은 window blur가 아니므로 중단하지 않는다. 브라우저 메뉴·개발자도구·OS 대화상자 등도 포커스 손실을 일으킬 수 있으므로 벌점을 주지 않는다. 전체화면은 선택 버튼이고 필수가 아니며 우회 방지 수단으로 주장하지 않는다.

## 가림과 정지 구현
- 최상위 불투명 overlay(z-index 충분히 높음), 배경 blur만 사용 금지. '학습이 일시정지되었습니다. 돌아오면 계속할 수 있습니다.' 표시.
- 학습 루트에 inert 적용, aria-hidden 적절히 관리. resume dialog로 focus trap, 재개 후 이전 의미 있는 포커스 복원. 가림 중 에디터 핫키·단축키 제출도 무효화.
- activeSeconds는 active 상태에서만 누적. hidden 시 마지막 delta 확정 후 time anchor를 비운다. 복귀할 때 숨긴 시간을 더하지 않는다.
- 애니메이션/CSS transition/자동 진행/오디오/동영상/타이머를 멈춘다. 비활성 상태에서는 SQL 실행 요청을 차단한다.
- SQL이 이미 실행 중이면 Worker를 종료하고 DB를 기준 스냅샷으로 복원한다. 실행 전 수정 샌드박스 상태는 스냅샷으로 보존한다. 요청 generation을 변경해 늦은 결과를 무시한다. 학생에게 '실행이 중단되었습니다. 다시 실행해주세요.' 표시.
- 입력 초안·조작 상태·힌트 단계는 보존하며 진행중 활동을 오답이나 완료로 자동 처리하지 않는다.
- 페이지 새로고침 후 저장한 단계와 초안을 복구하고 사용자 클릭으로 다시 학습을 시작한다.

이 기능은 집중을 돕는 UI다. 모든 외부 앱 탐지, 학생 감시, 부정행위 차단을 보장하지 않는다. 문서가 숨겨진 순간 OS가 표시한 마지막 화면이나 캡처까지 웹앱이 지울 수 있다는 보장도 하지 않는다.

## 단원 집중 학습(선생님 결정 2026-10-15)
- 범위: 컴퓨터 일반 `#/computer/unit/:unitId`(단원 보기·1~5단계), 같은 구조의 네트워크·프로그래밍·Data `#/network|programming|data/unit/:unitId`(2026-10-26 추가), 데이터베이스 `#/learn/:unitId…`·`#/challenge/CH-Uxx`. 모의고사·오답노트·최종 진단·정원은 범위 밖.
- 시작: 단원에 들어가면 시작 화면(규칙·지금까지 잠김 n/5)이 가리고, '전체화면으로 학습 시작'을 눌러야 시작한다(전체화면 요청은 클릭 안에서). 같은 단원 안의 단계·활동 이동은 전체화면 유지.
- 잠김: 학습 중(active) window blur, visibilitychange(hidden), pagehide(창 닫기·새로고침 포함), 전체화면 나가기(Esc)가 오면 화면을 잠그고 그 단원 잠김 1회로 센다. 같은 이탈의 연속 이벤트는 한 번만. 시작 직후 1.5초는 전체화면 전환 흔들림(blur·전체화면)만 미루고 끝난 뒤 다시 확인한다.
- 세지 않는 것: 시작 화면·잠긴 상태에서의 이탈, '쉬기', 앱 메뉴·링크로 단원 나가기, 앱의 로그인·'기본 브라우저로 열기' 버튼(이동 직전 멈춤).
- 5번째 잠김: 그 단원의 진도·점수를 지우고 단원 처음으로. 컴퓨터 일반(네트워크·프로그래밍·Data도 같음, 과목별로 따로)은 단계 기록·카드 맞추기·풀던 초안, 데이터베이스는 활동·체크포인트(변형 포함)·도전 기록과 서버의 그 단원 경험치·배지·활동 진도(`reset_db_unit`). 오답 기록·모의고사·진단·다른 단원은 그대로. 데이터베이스는 앞 단원을 초기화하면 다음 단원이 다시 잠긴다(기존 순서 규칙).
- 기기 간: 학습 기록에 단원별 초기화 표시(시각·횟수)와 잠김 시각 목록을 저장한다. 병합할 때 더 최근 초기화를 모르는 쪽의 그 단원 기록은 버린다. 서버 초기화를 못 했으면(오프라인 등) 다음 접속 때 초기화 시각까지의 기록만 지운다.
- 기기 지원: 전체화면 API가 없는 기기(아이폰 사파리·일부 앱 안 브라우저)는 전체화면 없이 진행하되 똑같이 센다. 단원 학습 중에는 화면 꺼짐 방지(Wake Lock)를 요청한다. 크롬·엣지는 전체화면 중 Esc를 페이지가 받게 해(길게 눌러야 전체화면 종료) SQL 편집기의 Esc가 잠김이 되지 않게 한다. 다른 브라우저에서는 Esc가 전체화면을 끝내 잠김으로 센다.
- 한계: 휴대폰 알림창 내리기·전화·화면 잠금 버튼도 이탈로 센다(선생님 결정). 실제 OS 수준 전환(Alt+Tab·최소화·알림)은 합성 이벤트로만 자동 검증했다.

## 화면 공유 유예(2026-10-26)
- 선생님이 '화면 보기 요청'을 보내고 학생이 허락 창에서 **화면 공유하기**를 누르면, 브라우저 자체 선택 창(getDisplayMedia)이 열려 학습 창이 포커스를 잃거나 전체화면이 풀릴 수 있다. 이 버튼을 누른 순간부터 스트림이 시작되거나 실패(취소)할 때까지는 blur·visibilitychange(hidden)·전체화면 나가기를 **잠김으로 세지 않고 멈추지도 않는다**(`allowSystemDialog`, src/features/focus/systemDialog.ts). 창 닫기·새로고침(pagehide)은 그대로 센다.
- 좁은 장치: 화면 공유 수락 버튼만 부르고, 한 번에 최대 2분이며 그 뒤에는 저절로 끝난다. 크롬은 탭·창을 공유해도 포커스가 학습 창에 머물도록 요청한다(Conditional Focus).
- 선택 창이 닫힌 뒤 0.4초 기다렸다가 다시 확인한다: 이 창이 보이고 포커스가 있고(단원이면) 전체화면이면 그대로 계속, 아니면 **세지 않고 멈춘다**('화면 공유 창 때문에 멈췄어요' → 다시 시작 클릭으로 전체화면). 판정은 순수 함수 `classifyLeave`·`afterSystemDialog`(focusMachine.ts)로 단위 테스트한다.
- 공유가 시작된 뒤에는 보통 규칙이 다시 적용된다: 공유 중이라도 다른 창·탭으로 가면 잠김 1회로 센다. 공유 시작·중지 자체는 잠김이 아니다.
