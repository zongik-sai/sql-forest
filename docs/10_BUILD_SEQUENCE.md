# Claude 순차 구현 절차

명세 읽기 순서: CLAUDE.md→01~13 번호 순. 구현은 아래 단계 순서대로 진행한다. 계획만 보고 멈추지 말고 자격정보 없이 할 수 있는 마지막 검증까지 완수한다. 다음 단계 진입은 해당 완료 조건 확인 후다.

| 단계 | 구현할 것 | 완료 조건 |
|---|---|---|
| S01 | 프로젝트 조사·Vite/TS 구조·스크립트·콘텐츠 타입·데모 | 앱 실행·typecheck·데모 상태 명시 |
| S02 | seed DB·Worker SQL 엔진·채점기·U03 한 활동의 세로 흐름 | 실제 SQL 결과와 기준 테스트 통과 |
| S03 | 12단원48활동·체크포인트36·최초진단5·최종진단12·변형36·도전12 | 콘텐츠 검증기·정답 SQL 검증·주제 누락 없음 |
| S04 | 학습지도·단계진도·힌트3단계·기본/도전·복습·결과 | 데모 전체 흐름과 잠금·해제 검증 |

콘텐츠 각 분류의 수량을 따로 검사한다. 핵심 활동, 확인문제, 진단, 변형문제, 도전문제를 합산한 숫자만으로 검증하지 않는다.

각 단계 완료 시 BUILD_STATUS.md에 상태(todo/in_progress/done/blocked), 관련 파일, 실행한 검증, 남은 외부 설정, 다음 작업을 짧게 기록한다. git 사용 가능하면 단계별 로컬 commit을 만들되 사용자 변경을 포함하지 않는다. 비밀정보를 commit하지 않는다.

컨텍스트가 부족하면 BUILD_STATUS와 명세를 업데이트하고 다음 실행에서 이어간다. 매 단계마다 사용자 확인을 요구하지 않는다. 설계 충돌은 이 문서/성장 문서/배포 문서의 v2 규칙으로 해결하고 이유를 기록한다. 외부 계정 접근 불가만으로 로컬 구현을 중단하지 않는다. 공개 배포는 사용자의 실제 후속 배포 지시와 계정 설정이 있을 때 수행한다.
